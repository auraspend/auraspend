# ADR 0009 — Relicensing to AGPL-3.0

**Status:** Accepted · 2026-09-30 · **Supersedes** the licence assumption in
ADR 0001 and ADR 0007 (both of which were written when the project was
Apache-2.0; neither decision is otherwise changed)

## Context

AuraSpend shipped as Apache-2.0. The question was whether to keep it.

This was not a formality, so it is worth recording what actually drove it —
including the parts that argue for staying permissive, because those are real
and they were weighed rather than waved away.

**The thing AGPL-3.0 uniquely does.** Under Apache-2.0, someone may take
AuraSpend, turn it into a hosted service, and never publish their changes. That
is lawful and it is the single most common way a project with a public
repository gets absorbed into a closed product. AGPL-3.0 §13 closes that path: a
modified version offered to users over a network must offer its Corresponding
Source. For a project whose whole value is that it can be audited, that is the
one guarantee worth paying for.

**What AGPL-3.0 does not do here, stated plainly.** §13 triggers on remote
network interaction. AuraSpend is an offline, on-device application; its only
network use is Google Drive backup, which talks to Google rather than to a
modified AuraSpend. So:

- No future cloud reskin of AuraSpend is actually caught by §13, because there is
  no AuraSpend server to point users at.
- Binary redistribution was *already* covered — both Google Play and F-Droid
  require source availability, which a public repository satisfies under either
  licence.

So the honest summary: **AGPL-3.0 buys a strong deterrent and a clear
normative statement, not a technical enforcement mechanism, for this specific
app.** It is still the right call, because the deterrent is the point, and
because it forecloses the proprietary-fork outcome permanently rather than
relying on good intentions.

**The costs, weighed.**

- *It is irreversible for this code.* Dual licensing or a commercial exception
  can be layered on later; going back to permissive cannot. Accepted: the
  project is not pursuing a proprietary variant.
- *It raises the contribution bar.* AGPL is the most copyleft of the common
  OSI licences, and some contributors decline to work under it. Accepted,
  partly mitigated by the explicit alternative in `CONTRIBUTING.md`: opening an
  issue instead of a pull request costs an author nothing.
- *It constrains the dependency set.* Everything currently in the graph is
  Apache-2.0 or MIT, which flows one-way into AGPL-3.0. Any future GPL-2.0-only
  or non-commercial dependency would become a blocker. Accepted, with the
  constraint recorded in `AGENTS.md` so it is discovered at proposal time rather
  than at merge time.
- *It required a copyright assignment.* This one is a genuine obligation rather
  than a trade-off, and is covered under "How this is protected".

## Decision

**AuraSpend is licensed under the GNU Affero General Public License v3.0 or
later, effective from release 0.1.1.**

- `LICENSE` holds the verbatim AGPL-3.0 text, fetched from gnu.org rather than
  transcribed, so it is byte-exact.
- Releases at and before 0.1.0 remain Apache-2.0. The relicensing is
  prospective, and the website says so.
- **Third-party components are unaffected.** They stay under their own licences.
  The bundled ONNX Runtime is MIT, the font is OFL, AndroidX and the
  Google libraries are Apache-2.0, and the runtime-downloaded model is
  Apache-2.0. The AGPL covers AuraSpend's own source and nothing else. Every
  mention of "Apache-2.0" that referred to a dependency was deliberately left
  alone — a global find-and-replace would have made false licensing claims about
  third parties.
- **`or later` is offered.** It costs nothing, and it means a future FSF revision
  does not force a relicensing decision.

## Consequences

- **A modified AuraSpend cannot be shut.** The §13 obligation travels with the
  code to anyone who modifies it, which is the specific outcome this was chosen
  to prevent.
- **Contributions need a copyright assignment.** Without one, the first external
  contributor would make every future relicensing impossible, recreating exactly
  the problem this ADR solves. `CONTRIBUTING.md` and the pull-request template
  both require the confirmation, and the file explains why rather than just
  demanding it.
- **The app must ship the license text.** AGPL §4 requires a copy of the License
  to accompany the work, so this is now a hard product requirement rather than a
  nicety: Settings → About → Open-source licenses carries the full text and the
  third-party attributions.
- **Historical records are annotated, not rewritten.** ADR 0001 and ADR 0007
  still say Apache-2.0 where they were written, with a pointer to this ADR.
  Rewriting a past decision to match the present is how an ADR log stops being
  usable.
- **The in-app licence line became dynamic.** The About version now reads
  `BuildConfig.VERSION_NAME` rather than a hand-typed string, because it had
  already drifted once — a private changelog claimed 0.2.1 while the app said
  0.1.0, and nothing caught it.

## How this is protected

- `AGENTS.md` records that a new dependency must be AGPL-3.0-compatible, so the
  constraint is applied when a dependency is proposed.
- `CONTRIBUTING.md` and the PR template carry the copyright assignment.
- `tools/check_license.sh` fails CI if the licence string is inconsistent across
  `LICENSE`, `README`, the app's string resources, and the website. The licence
  had already drifted across eleven files with nothing detecting it, which is
  the only justification for a check this blunt.
- The full text and attributions ship in the app, satisfying §4.

## Rejected alternatives

| Option | Why not |
|---|---|
| Stay Apache-2.0 | Leaves the proprietary-fork outcome open. This is the one risk the change was made to close. |
| MIT | Same problem, and it additionally forbids relicensing outright. |
| GPL-3.0 (not Affero) | GPL's copyleft stops at distribution. A modified AuraSpend run as a service never gets distributed, so a hosted fork would stay closed. This app is the case GPL does not cover. |
| AGPL-3.0 **without** a CLA | Would work today and fail at the first external contribution, leaving the project permanently stuck on whatever licence it had then. The assignment is what keeps this decision reversible. |
| Dual AGPL/commercial | Defensible, and it preserves an option to sell. Rejected because it reintroduces exactly the proprietary path the change exists to close, and because a project this size has nothing to sell a licence exemption for. Revisit if that changes. |
