Changelog

Every release, newest first. This mirrors the canonical CHANGELOG.md in the repository, which follows Keep a Changelog.

0.1.2 — 11 October 2026

The reliability release. A 32-finding code review is fixed end to end — the on-device categoriser had been silently inert in production, and three separate paths could lose, hide or overwrite real money — plus Google Drive backup, a currency picker, and guarded release signing.

Added

  • Google Drive backup. The app could restore from Drive but had no way to create a backup; Settings → Data now has "Back up to Google Drive" and "Restore from Google Drive". The backup carries every user-owned table inside one transaction, and restore (a replace, not a merge) asks for confirmation first.
  • Currency picker. 30 currencies, captured offline as a source constant — no network at runtime — with the device currency preselected and first, on a fourth onboarding page and a Settings → Finance row, plus a "Match my device" reset. Formatting only: no FX conversion, and the picker says so.
  • Signed, approval-gated builds for pull requests to main, so a signing regression is caught before merge. Releases stay tag-driven.
  • Release signing moved to a protected GitHub environment: required reviewer, restricted to main, version tags and main-targeting PRs.
  • The test suite grew 256 → 350, and a privacy-claims check now fails CI if an absolute "nothing leaves your phone" claim appears without its exception.

Changed

  • Public wording is honest about distribution: "Download APK" claims are gone until a release is actually published — build from source; the Play listing is staged, not published.
  • The privacy copy is qualified in-app and in the policy: the only upload is the Drive backup the user starts, and the policy now lists the unrecognized-message table and its 30-day purge.
  • The shipping build no longer allows runtime heap profiling; the dev build keeps it for baseline-profile generation.
  • Lottie (attributed but never in the build) and its licence text are removed; every attribution was re-checked by the licence gate.

Fixed

  • The on-device categoriser was inert in production. The model asset is little-endian; the reader parsed big-endian, failed, and the failure was swallowed while settings said "ready". The codec now validates the file, the asset digest is pinned, a test decodes the real asset, and readiness reflects a failed load. Measured accuracy is unchanged — the fix made the numbers real.
  • The model's safety gate was dead code (wrong probability semantics); it now uses verdict confidence, and a test fails if the gate becomes unreachable again.
  • A duplicate SMS id could delete the user's edited transaction (SQLite REPLACE is delete-then-insert). Writes are now update-if-present, insert-if-absent, and CSV import is one all-or-nothing batch.
  • A fresh install never ingested its SMS history — a single watermark skipped everything older than the newest 500 messages. The scan now walks history downwards with its own cursor.
  • Deposits and refunds with a balance tail were dropped, and sender-first bank routing had zero production callers; both fixed.
  • Triage said "Saved" before the save happened; the confirmation now fires only after the write, and failures surface as errors.
  • Restore re-imported unmasked message text from old backups; restore now masks the SMS queue and unrecognized messages.
  • The 30-day purge was never called; it now runs on the background classification tick — and the SMS history is explicitly never swept.
  • A v1 database could have been wiped instead of migrated; the missing migration is added and schemas are exported for review.
  • Hardcoded ₹ removed from app chrome (all money text follows the chosen currency); ~30 strings localized (EN/HI parity 489/489).
  • The R8 and native-runtime audits are now CI gates — the native audit had ignored its own arguments and could not fail.

Removed

  • Dead code the review found: duplicate-detection stubs, an unreachable dialog, and a scan-cursor helper whose premise was the ingest bug.

0.1.1 — 30 September 2026

The AGPL and encoder release: the on-device categoriser shrank from 468 MB to 22 MB, and the project changed licence.

Changed

  • Licence: Apache-2.0 → AGPL-3.0-or-later, so a modified AuraSpend offered to users over a network must offer its source too. Irreversible for this code.
  • On-device categoriser: 468 MB generative model → 22 MB int8 encoder (nearest-centroid over ONNX Runtime). Five candidate runtimes were measured before choosing.
  • Two ABIs instead of four — AAB 35.4 → 20.5 MB. The model downloads at runtime after explicit opt-in, and its SHA-256 is verified before use.

Fixed

  • A fresh install silently downloaded the model and enabled auto-read with no prompt; consent is now a tap.
  • Swipe-to-save and swipe-to-delete were silent no-ops (a deprecated Compose callback); both now work and are undoable.
  • The triage inbox never drained; Plan reported ₹0 while Dashboard showed real spend; several enum and formatting crashes were made unbreakable.

Added

  • In-app open-source licences screen (an AGPL §4 requirement) and a contributor CLA.

0.1.0 — 13 May 2026

First alpha. Material 3 UI, bank SMS classification, budgets, subscriptions, savings goals and Google Drive backup, under Apache-2.0 at the time.
